## Context

The atomic one. A type parameter cannot be half-changed, so every `BasicNode`
mention compiles or none does — 68 occurrences across 19 files. Sized `l` for
that reason and not because it is conceptually hard; it needs a spec because the
tactic for keeping it reviewable is the actual decision.

**Keep it purely mechanical.** `GgapNode` gains both fields, but this child
populates only `cluster_addr` and leaves `client_addr` empty at every
construction site. `add_learner` keeps its `String` signature. No semantic change
lands here — tk-fd58 and tk-10b7 harvest separately. A reviewer should be able to
read this diff as a rename.

Source sites: `config.rs:11` (the `declare_raft_types` line), `network.rs` (9 —
mostly `RPCError<u64, BasicNode, _>` type params plus `new_client`),
`state_machine.rs` (6 — `StoredMembership<u64, BasicNode>` encode/decode),
`node.rs` (5), `split.rs` (2). Tests and benches: 11 more files, constructors
only.

Breaks on-disk format twice over — serialized `Entry` in the log and
`StoredMembership` in snapshots and the meta keyspace. Per the epic's Q2 that is
a data-dir wipe, not a migration, but say so in the commit message because the
failure mode on a stale dir is a decode error rather than a clear message.

Worth considering in the spec: whether a `type` alias introduced first and
flipped second makes this two `m` changes instead of one `l`. The obstacle is
the handful of `.addr` field accesses, which an alias does not cover.

## Problem

Raft membership can only carry one address per node, because
`GgapTypeConfig::Node = BasicNode` and `BasicNode` has a single `addr` field. So
a client address cannot reach committed consensus state at all: `add_learner`
discards the one it is given (tk-fd58), a split-created shard bootstraps without
one (tk-10b7), and the gossip directory has to originate and merge client
addresses field-wise because membership can never supply them (tk-11b6). Every
other child of this epic is blocked on the type parameter, and a type parameter
cannot be half-changed — 68 occurrences across 19 files compile together or not
at all.

## Approach

Introduce `GgapNode { addrs: NodeAddrs }` in `ggap-consensus` and point
`declare_raft_types!` at it. `NodeAddrs` (in `ggap-types` since tk-f2fc) already
derives every bound openraft's `Node` requires — `Debug + Clone + Default + Eq +
PartialEq + Serialize + Deserialize + Send + Sync + 'static` — and `Node` is a
blanket-impl marker trait, so the wrapper needs no `impl Node` block and
`ggap-types` gains no openraft dependency. `GgapNode` gets
`cluster_addr()` / `client_addr()` accessors, `From<NodeAddrs>`, a
`cluster_only(addr)` constructor mirroring `NodeAddrs::cluster_only`, and
`Display` printing the cluster address (openraft does not require it; error logs
that used to print a `BasicNode` read better with it).

**Rejected: `Node = NodeAddrs` directly** (Q1). It compiles with zero new code
and no conversions, but every future consensus-only field — placement zone,
voter metadata — would have to land in the shared domain type. The wrapper's
cost is one conversion seam at the `ggap-types` boundary in tk-10b7.

**Rejected: alias first, flip second** (Q2), the two-`m` split the task text
floats. An alias covers the ~30 type-parameter mentions but not the ~20
`BasicNode { addr }` / `BasicNode::default()` construction sites that make up the
bulk of the 11 test and bench files, so PR1 would be a provable no-op and PR2
would still touch nearly every file.

The change stays **purely mechanical**: `client_addr` is `String::new()` at every
construction site, `add_learner` keeps its `String` parameter, `ClusterStatus`
keeps `Vec<(u64, String)>`, and the gossip merge rule is untouched. A reviewer
should read the diff as a rename. tk-fd58 and tk-10b7 harvest the new field.

## Risks

- **A stale data dir fails obscurely.** Any `.data` directory from before this
  commit decodes to a bincode error deep in `state_machine.rs` or the log reader.
  Wipe local test clusters; the commit message must say so.
- **`three_node_cluster.rs:1050`** asserts that a client address can only travel
  by gossip. That assertion stays *true* here — nothing populates membership's
  client address until tk-fd58 — so it must keep passing unmodified. If it needs
  editing, scope has leaked.
- **`sim_cluster.rs`** implements `RaftNetworkFactory` independently of the real
  `network.rs`, so its nine sites are the ones most likely to produce type-inference
  errors that tempt a non-mechanical fix. Per the DST notes, its
  `RPCError<u64, BasicNode, _>` helpers exist precisely because a generic error
  helper does not infer — keep them explicit.
- **`Display` on `GgapNode`** changes log and error *text* wherever a node was
  formatted (`ForwardToLeader`, openraft's own membership logs). Printing the
  cluster address keeps it identical to `BasicNode`'s output; anything else
  silently changes what operators grep for.

## Outcome

22 files, +297/−147. Mechanical as specced: no test assertion moved, only
constructors and imports. tk-3080 folded in and closed with it.

**The spec's premise about openraft held, and is worth remembering.** `Node` is a
marker trait with a blanket impl over `Debug + Clone + Default + Eq + Send +
Sync + 'static + serde` — there is no `impl Node for GgapNode` anywhere in the
diff, and `Display` is required only of `NodeId`, not `Node`. That is why the
wrapper cost nothing structurally and why `Node = NodeAddrs` was a real
alternative rather than a hypothetical one (Q1).

**`grep -r BasicNode crates/` returns one hit**, not zero: the doc comment on
`GgapNode`'s `Display` recording that the output deliberately matches what
`BasicNode` printed, so operator greps keep working. Kept deliberately — the
acceptance box is ticked with that exception stated, because deleting the comment
would delete the reason the impl exists.

**Four comments needed rewording, not renaming.** `gossip.rs:199`,
`ggap-types/src/lib.rs:140`, `three_node_cluster.rs:1048` and
`docs/ggap-consensus.md:80` all explained a limitation as "`BasicNode` has one
address field". After this task the limitation is that nothing *populates* the
second field, which is a different sentence and a different task (tk-fd58). A
bulk substitution turns those into confident falsehoods; they were rewritten by
hand. Anything doing the same trick for tk-fd58 or tk-11b6 should expect the
same: the comments are load-bearing, and they say *why*, not *what*.

**Review note applied.** The first cut also carried `From<GgapNode> for
NodeAddrs`, which nothing calls — the reviewer flagged it as dead public API and
it is gone. `From<NodeAddrs> for GgapNode` stays because Q1's answer asked for
it; tk-10b7 adds the reverse when it has a caller.

**`GgapNode::cluster_only("...".into())` does not infer.** `impl Into<String>`
plus a bare `.into()` at the call site leaves the target type ambiguous
(`E0283`). Pass the `&str` directly. This bit once in
`raft_metrics_task.rs` and will bite again wherever a `BasicNode { addr: x.into() }`
literal gets mechanically rewritten.
