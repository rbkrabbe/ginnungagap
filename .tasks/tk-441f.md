## Context

The atomic one. A type parameter cannot be half-changed, so every `BasicNode`
mention compiles or none does — 68 occurrences across 19 files. Sized `l` for
that reason and not because it is conceptually hard; it needs a spec because the
tactic for keeping it reviewable is the actual decision.

**Keep it purely mechanical.** `GgapNode` gains both fields, but this child
populates only `cluster_addr` and leaves `client_addr` empty at every
construction site. `add_learner` keeps its `String` signature. No semantic change
lands here — tk-fd58 and tk-10b7 harvest separately. A reviewer should be able to
read this diff as a rename.

Source sites: `config.rs:11` (the `declare_raft_types` line), `network.rs` (9 —
mostly `RPCError<u64, BasicNode, _>` type params plus `new_client`),
`state_machine.rs` (6 — `StoredMembership<u64, BasicNode>` encode/decode),
`node.rs` (5), `split.rs` (2). Tests and benches: 11 more files, constructors
only.

Breaks on-disk format twice over — serialized `Entry` in the log and
`StoredMembership` in snapshots and the meta keyspace. Per the epic's Q2 that is
a data-dir wipe, not a migration, but say so in the commit message because the
failure mode on a stale dir is a decode error rather than a clear message.

Worth considering in the spec: whether a `type` alias introduced first and
flipped second makes this two `m` changes instead of one `l`. The obstacle is
the handful of `.addr` field accesses, which an alias does not cover.
