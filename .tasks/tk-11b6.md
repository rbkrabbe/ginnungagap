## Context

Where the compensation gets deleted.

`refresh_local` (gossip.rs:179-233) currently does two things with addresses:
seeds this node's own entry from config, then merges membership as *cluster-only*
entries because membership had no client address to give. After tk-fd58 it does,
so both halves collapse into one: derive the full entry from `raft.metrics()`.

- Delete the self-seed. A node's own entry arrives through membership like
  everyone else's, which also removes the "originated by exactly one node"
  property that made the whole thing fragile.
- `merge_directory`'s field-wise rule and the empty-means-unknown convention were
  scaffolding for that asymmetry. Re-examine both — this child should be able to
  simplify the merge, not just feed it better data. If the field-wise rule
  survives, say why in the task.
- `GossipTask::new`'s `self_client_addr` parameter goes away, and with it the
  seeding in `ShardRegistry::new` at main.rs and in every test harness.
- tk-7664 (a node hosting no shards never publishes itself) may be resolved or
  made moot here — check it rather than leaving it stranded.

## Acceptance

- [ ] With the gossip task stopped entirely, a node still reports both addresses
      for every peer in a shard it hosts.
- [ ] No node self-seeds an address; `GossipTask` takes no address argument for
      the client listener.
- [ ] The registry unit tests reflect whatever merge rule survives, and any rule
      that is kept has a stated reason.
- [ ] tk-7664 is closed or explicitly re-scoped.
- [ ] Full checklist green: fmt, clippy -D warnings, build, test.
