## Context

The first increment, and it ships alone: the registry gains the ordering rule
that the old self-seed never had, while the membership-derived feed keeps
running. Nothing depends on it yet, which is what makes it safe to land first.

- `NodeAddrs` in the directory becomes a descriptor carrying an incarnation
  (`registry.rs` directory map, `GossipNode` in `types.proto`).
- `merge_directory` orders by incarnation, highest wins, replacing the
  whole-value last-write-wins rule tk-11b6 left in place. Its provenance
  argument does not survive this — rewrite that comment, do not patch it.
- `GossipTask` publishes this node's own descriptor each tick, from config.
  This is the self-seed restored; say so in the code comment without narrating
  tk-11b6.
- The membership-derived merge stays for now. Both feeds write the same map, so
  decide and document which wins while they coexist — a membership entry has no
  incarnation.
- No liveness or last-seen tracking. The directory carries addresses and an
  incarnation, nothing else.

## Resolution

`NodeDescriptor { addrs, incarnation }` lands in `ggap-types` beside
`NodeAddrs`, and `GossipNode` carries `incarnation` on the wire.
`merge_directory` orders by incarnation, highest wins, ties to the incoming
entry.

**Coexistence rule:** there is exactly one incarnation-0 feed — the
membership-derived merge in `gossip.rs`, which copies what a member advertised
when it joined rather than what that member says about itself. (`AddLearner`
writes only into membership; it does not touch the registry.) A node's own
publications start at 1 and therefore always outrank that feed, regardless of
arrival order. Ties going to the incoming entry keep the derived feed
last-write-wins among its own entries, which preserves the retraction semantics
from tk-11b6 — a stale address can still be withdrawn before the node it
describes has published anything. Both directions of the rule are
mutation-checked: dropping the comparison fails three tests, and flipping the
tie to the incumbent fails three others.

An absent proto field decodes to 0, so a peer on the pre-incarnation wire
format ranks as a hint and can never outbid a self-published descriptor.

`refresh_local` publishes self *before* the empty-router early return, which
reverses tk-7664's resolution on purpose: that task concluded a shardless node
should publish nothing because the directory was membership-derived. It is not
any more.

The boot counter that epic Q1 settled is **not** here — `main.rs` passes a
constant `SELF_INCARNATION = 1`. This is a human-accepted intermediate state,
not an oversight; the cost is stated plainly:

Every node publishes at rank 1, so a node that restarts at a new address ties
with the copy its peers already hold. Ties go to the incoming entry, so the new
address propagates by arrival order rather than by rank — it does converge,
since the moved node is the only source still republishing, but it can oscillate
while stale copies are in flight and the guarantee is arrival-order, not the
ordering the epic specifies. The membership-derived feed can no longer correct
it either, being permanently outranked at 0.

One consequence worth naming, because it is the strongest argument for doing
tk-98e9 soon: since ties go to the incoming entry, a peer's stale copy of *our
own* descriptor overwrites our self-entry in `merge_gossip_state`, and
`exchange_with` re-snapshots per peer — so within a single round the moved node
can re-emit the stale address about itself to the next peer, until the next
`refresh_local` restores it. Sole authorship is briefly inverted at the author.
It lengthens the transient; it does not break convergence.

Accepted because nothing resolves addresses through the directory yet:
`GgapNetwork` still reads them out of membership until tk-cc52. The window is
this commit until tk-98e9 lands.

tk-98e9 carries the fix, and is blocked on a question this task surfaced: every
storage key is shard-prefixed, and a boot counter is node-scoped, so there is
nowhere to put it that does not either burn a second sentinel prefix (the
`SHARD_MAP_PREFIX` precedent) or make the hard constraint conditional. tk-c593's
premise that `meta` already holds "other node-scoped keys" is wrong — it holds
none.
