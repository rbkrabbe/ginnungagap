## Context

Rust stable 1.98.0 (released 2026-08-18) fires `clippy::result_large_err` on
every tonic-generated service method, because the `Err` variant is
`tonic::Status` at 176 bytes against the lint's 128-byte threshold. 15 errors in
`ggap-proto`, all in `OUT_DIR/ginnungagap.v1.rs`, none in code anyone here
wrote.

CI runs `rustup update stable` on every run, so it picked this up the moment the
release landed. Reproduced at 71478ef — the base of the tk-8978 branch — with
the identical 15 errors, so it is a toolchain bump and not any PR's doing. It
blocks every PR that touches code until fixed.

`crates/ggap-proto/src/lib.rs` wraps the generated code in a single `pub mod v1`
containing nothing else, so the allow sits on that module and reaches exactly the
generated code.

That is not the whole story: 15 more fire in `ggap-server`, all in the *inherent*
impl blocks of the four service types. Those are hand-written, but their `do_*`
helpers feed the tonic trait methods directly, so `tonic::Status` is imposed on
them transitively — the choice is where to put the allow, not whether the error
type could be smaller. The trait impls themselves do not fire; clippy skips
signatures a trait dictates.

The toolchain stays floating, which was a deliberate choice: pinning was
considered and declined. The same shape of breakage can recur on a future
release.

## Acceptance

- [x] `cargo clippy --all-targets -- -D warnings` passes on Rust 1.98.0.
- [x] The allow is scoped to code whose error type tonic imposes: the generated
      `v1` module, and the four service inherent impls. No other module loses
      the lint.
- [x] Full checklist green: fmt, clippy -D warnings, build, test — verified on
      both 1.98.0 (CI's stable) and 1.93.1 (the local default).

## Resolution

Scoped allows in five places rather than a crate-level one, so a genuinely
oversized error type of our own still gets caught everywhere else.

The original acceptance said the allow would cover "only the generated module,
not hand-written code". That was written before running 1.98.0 against the whole
workspace and is wrong: `ggap-server`'s service helpers need it too. Corrected
above rather than quietly satisfied.

Pinning the toolchain was offered and declined, so CI keeps floating on
`rustup update stable` and a future release can break an unrelated PR the same
way. The diagnosis path is in the Context section.
