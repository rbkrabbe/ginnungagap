## Context

`admin_service.rs:63-73` returns membership-derived `NodeInfo` for a hosted
shard and falls back to `ids_to_node_infos` (:108) for the rest. Once membership
has no addresses the two paths collapse into one: ids from membership or the
gossiped `ShardEntry`, addresses always from the directory.

Watch the `last_observed_age_ms` semantics — hosted shards report 0 today, and
that should stay tied to the consensus data, not to directory freshness.

## Acceptance

- [x] One address-resolution path, used for hosted and non-hosted shards alike.
      `ids_to_node_infos` (`admin_service.rs:107`) is the only place a
      `NodeInfo` address is built; the hosted path calls it at :66/:70 and the
      gossiped path at :83/:87.
- [x] `last_observed_age_ms` still distinguishes hosted, gossiped and never-seen:
      `Some(0)` / `Some(age)` / `None`, in both `do_cluster_status` and
      `do_list_shards`. Covered by `three_node_cluster.rs:1194-1223`.
- [x] Full checklist green — no code change was needed here.

## Outcome

Absorbed by tk-51b4 rather than done separately. `ClusterStatus` exposed
`Vec<(u64, NodeAddrs)>` straight out of Raft membership, so it could not survive
`GgapNode` losing its addresses; collapsing it to id lists forced the hosted
path onto the directory, which is exactly the collapse this task describes. The
`last_observed_age_ms` warning in the context was heeded: the field stayed tied
to the consensus snapshot and was not repurposed to describe directory
freshness.

That leaves a gap this task's framing did not anticipate — see the task filed
from it — because `age = 0` on a hosted shard no longer covers the addresses
beside it.
