## Context

`ClusterStatusResponse.last_observed_age_ms` reports how old the *consensus*
snapshot is: `Some(0)` for a shard this node hosts, `Some(age)` for one it knows
only by gossip, `None` for one it has never heard of. That is the right meaning
and tk-00c0 deliberately kept it.

It used to cover the whole response. For a hosted shard, ids and addresses both
came out of Raft membership, so `age = 0` was true of everything in it. Since
tk-51b4 the ids come from openraft and the addresses from the directory, which
may be arbitrarily stale — a node that moved and whose descriptor has not
reached this one yet is reported at its old address, next to `age = 0`.

Nothing can report directory freshness today: `ShardEntry` carries a
`last_updated` instant, but `NodeDescriptor` carries only an `incarnation`,
which orders one node's publications and says nothing about time. So this is a
missing field before it is a missing report.

Worth deciding whether a consumer needs it at all. `age = 0` is not *wrong*
about consensus; the risk is a reader generalising it to the addresses. If no
consumer would act on address freshness, documenting the narrower meaning is the
whole fix.

## Acceptance

- [ ] Either the response distinguishes consensus freshness from address
      freshness, or the narrower meaning of `last_observed_age_ms` is documented
      where a consumer will see it.
- [ ] If a timestamp is added to `NodeDescriptor`, it uses `tokio::time` and
      survives the gossip round-trip.
- [ ] Full checklist green: fmt, clippy -D warnings, build, test.
