## Context

`ggap-consensus/src/lib.rs` carries `pub use ggap_types::NodeAddrs`, which is the one place the crate re-exports a type it does not own. It exists so tk-f2fc could move `NodeAddrs` into `ggap-types` without touching the seven call sites that import it from `ggap_consensus` — updating them would have made that task a 10-file change and forced a resize off `s`, for a refactor whose whole point was to be invisible.

The cost is two valid import paths for one type, which drifts: new code picks whichever it sees first, and the comment asking for `ggap_types::NodeAddrs` is the only thing keeping it consistent.

Importers to move: `gossip.rs`, `ggap-node/src/main.rs`, `three_node_cluster.rs`, `cors_preflight.rs`, `rpc_metrics.rs`, `trace_propagation.rs`, `benches/kv_write.rs`.

Blocked on tk-11b6 because tk-441f, tk-fd58 and tk-11b6 all churn those same files. **If any of them ends up editing an import line anyway, fold the change in and close this as done rather than leaving a separate PR that only moves `use` statements.** This task exists to make sure the re-export is not still there in six months, not to insist on its own commit.

## Acceptance

- [x] `pub use ggap_types::NodeAddrs` is gone from `ggap-consensus/src/lib.rs`.
- [x] The seven importers name `ggap_types::NodeAddrs` directly.

## Outcome

Folded into **tk-441f** and shipped in that commit, exactly as this task's context
asked: tk-441f rewrote the imports in all seven files anyway, so a separate PR
would have moved `use` statements and nothing else. Landed ahead of its
`blocked_by` (tk-11b6) for the same reason — the blocker existed only to avoid
churning files twice, and tk-441f churned them first.
