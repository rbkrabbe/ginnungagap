## Context

Any `tk` write (`tk claim`, `tk review`, presumably others) round-trips the task
file through a parser that reads a multi-line TOML array as the string `"["` and
writes that back, silently discarding the entries.

Observed on tk-10b7, whose `touched` list of 10 paths was destroyed twice — once
by `tk review tk-10b7 pass` and again by `tk claim tk-10b7`. Both times the list
had to be restored by hand before committing.

Reproduce: take a task file whose `touched` is a multi-line array, run any `tk`
mutation against it, and diff.

`touched` feeds the commit-scope hook, so a silently emptied list means the hook
stops guarding the paths the task actually claimed.
