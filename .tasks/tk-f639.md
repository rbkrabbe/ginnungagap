## Context

tk-4822 gives a retired node two behaviours: the **gate** (KV, Admin and Raft
answer `UNAVAILABLE`, gossip does not) and the **teardown** (stop each shard's
Raft group, its TTL GC task and its metrics task; drop the shards from the
router; set `ggap_node_retired`). Only the gate is tested.

`a_retired_node_serves_gossip_and_refuses_everything_else` cancels the
harness's `retired` token, which reaches the serve configs and nothing else:
`start_node` has no equivalent of `ggap-node`'s retire handler. So
`shard_tasks.cancel()`, `router.remove_shard()`, `raft.shutdown()` and the
gauge set exist only in `main.rs` and nothing drives them.

That is the fix for the one behavioural bug tk-4822's review found. Its
consequence if it regresses is not subtle: `refresh_local` keeps publishing a
`ShardEntry` per router-held shard with `version` rising every tick, and
`merge_entry` has no tombstone check and orders on `(term, version,
leader_origin)` — so a retired node still publishing wins at every peer on
version alone, and that is the view `AdminService` answers `ClusterStatus`
from for shards it does not host. It was caught once by review; nothing would
catch it twice.

## Do not mirror the handler in the harness

The obvious move — give `start_node` a retire handler like `main`'s — tests
the duplicate rather than the code that ships, and the two would drift
silently. Extract the teardown instead: a function over the router, the token
and the Raft handles, called by `main` and by a test. Then the test drives the
real thing.

That also closes part of tk-4822's unticked acceptance: the gauge set moves
with the teardown and becomes assertable. The *startup* half of the
quiesce decision stays binary-only and belongs to [[tk-d2bb]] — two tasks now
blocked on the same missing harness, which is the argument for taking that one
via `CARGO_BIN_EXE_ggap-node` rather than by extracting more functions.

## Acceptance

- [ ] The teardown is a function `main` calls, not inline in its retire task.
- [ ] A test drives that function and asserts: the router holds no shard
      afterwards, so `refresh_local` publishes no `ShardEntry`; the Raft groups
      are shut down; the shard-scoped tasks stop.
- [ ] A peer does not see a retired node's `ShardEntry` version keep rising —
      the regression that review caught, asserted rather than reasoned about.
- [ ] Full checklist green: fmt, clippy -D warnings, build, test.
